# 06 デバイス画面・音声

担当：B（表示コンポーネント）。カメラ取得・動きスコア・API・音声合成・**1 秒ごとの送信と自動ヒントのループ（`web/lib/loop.ts`）**は高橋が書き、B はそれを呼んで表示するだけ。

**10/16 夜の改訂**：Hack Day 版では「静かに」ボタンと `quiet`・`away` は作らない。SSE は廃止。セッションは `/ops` で作る。

## 役割

デバイス画面 `/device` は、机の横のスマホで開きっぱなしにする 1 画面。やることは 5 つ。

1. カメラで手元を映し続ける（映像は画面に出す。学習者が「何が映っているか」を常に見られるように）。
2. 1 秒ごとに動きスコアを計算してサーバへ送り、返ってきた状態を表示する。
3. サーバの指示でフレームを送り、ヒントを要求する。
4. ヒントを声と字幕で出す。
5. ボタン（はじめる・ヒント・できた・次へ・おわる）。

## 画面の配置（スマホ縦持ち）

```
┌──────────────────────────────┐
│ scripted（scripted のときだけ黄色帯） │  ← ヘッダ：モードと接続の警告だけ（10/18 にシート名と問題番号を外した。初見の問題なので意味が無い）
├──────────────────────────────┤
│                              │
│      カメラ映像（手元）        │  ← 常時表示。暗いときは「明るさが足りません」を重ねる
│                              │
│  2x - 7 = 4x + 3             │  ← AI が読み取った問題文（左寄せ。10/18 に状態バッジから置き換え。「はじめる」の 3 秒後に読む。ADR 0034）
├──────────────────────────────┤
│ 「右辺に移したときの符号、      │  ← 字幕（直近のヒント・チェック結果）。大きい文字
│   もう一回見てみて」           │
├──────────────────────────────┤
│ [ ヒント ]      [ できた ]    │  ← 主ボタン 2 つ（大きい）
│      [ 次へ ]  [ おわる ]     │  ← 副ボタン 2 つ（小さい）
└──────────────────────────────┘
```

PC（横持ち）では映像を左、字幕とボタンを右に置く。部品は同じ。

- 横持ちのときと、幅 1024px 以上のときは 2 列にする。左に問題文、映像（列の幅いっぱい）、「はじめる」の前の選択。右にキャラクターと字幕、その下にボタン。
- 縦持ちでは映像を右上に小さく出す（幅 112px。幅 640px 以上の画面では 192px）。
- 字幕は画面の高さの 40% までにし、長い文は字幕の中でスクロールする。ボタンの枠は画面の下に貼りつける（sticky）。字幕が長くても、背の低い画面（iPhone SE の Safari の 375×553、横持ちの 667×375）でも、ボタンは画面の中にある。収まらない分はページがスクロールする。
- 「となりに座る人」と秒数の選択は `created` のときだけ出す。見守りの間は、字幕とボタンに場所を使う。

## 状態と表示

10/18 から状態のバッジは出さない（高橋の判断。状態はキャラクターの表情と字幕で分かる）。「バッジ」の列は以前の仕様で、色はキャラクターの表情の参考にする。

| 状態 | バッジ（出さない） | 色 | 字幕 | 音 |
|---|---|---|---|---|
| `created` | はじめる前 | 灰 | 「スマホを立てて、手元が映るようにしてね」＋「止まったと判定する秒数」の選択（10 秒・20 秒・30 秒・1 分・3 分・5 分・10 分・20 分。既定はセッションの値） | なし |
| `watching` | 見守り中 | 緑 | 「はじめる」でカメラが動いたら「見守りを始めるよ」（読み上げと同じ文。音を消していても始まったと分かるように）。そのあとは直近のまま | 最初の 1 回だけ「見守りを始めるよ」 |
| `still` | 見守り中（点滅なし。still を学習者に見せない） | 緑 | 直近のまま | なし |
| `stuck` | 考え中？ | 黄 | 直近のまま | なし |
| `speaking` | となり | 青 | ヒント文 | 読み上げ |
| `cooldown` | 見守り中 | 緑 | ヒント文のまま | なし |
| `checking` | 見てるよ | 青 | 「見てるよ…」 | なし |
| `ended` | おつかれさま | 緑 | 選んだ人の終わりの言葉（`getSession` の `persona_options` の `end_message`。40 字を超えるか無ければ `web/lib/personas.ts` の既定）。最後の問題の正解で終わったら、判定の文と並べる | 終わりの言葉を 1 回 |

- `still` を表示で区別しないのは意図的。「止まっている」とカウントされていることを見せると、学習者がカメラを意識して手を動かす。
- 「考え中？」のバッジは出さない（ADR 0042）。先読み（ADR 0028）で詰まりとほぼ同時にヒントが届き、声は合成の 1〜2 秒後に出る。
- `ended` になると（読み込み直したときは最初の `getSession` の `state` が `ended` なら）、映像の下に「記録を見る」を出す。押すと `getSession` をセッションのトークンで 1 回呼び、`/device` の上に「今日の記録」を重ねて開く（`/log` の詳細と同じ中身。`web/app/_components/record/`。問題は、詰まったか、ヒントか「できた」の結果があるものと、飛ばしたものだけ出す）。「とじる」で戻る。読み込み中は「読み込み中…」、失敗したら映像の下に「記録を読めませんでした」。

## 開始の手順（音声のアンロック）

ブラウザは、ユーザー操作なしに音を出せない。「はじめる」ボタンのクリックハンドラの中で次を順に行う。**1〜3 は `unlockSpeech()` と `startCamera(video)` の中身で、B はこの 2 つと `startSession` を順に呼ぶだけ。`speechSynthesis` や `getUserMedia` を `web/app` に書かない。**

1. `speechSynthesis.speak(new SpeechSynthesisUtterance(""))` を 1 回呼ぶ（無音。これで以後の自動読み上げが許可される。iOS Safari で必須）。
2. `navigator.mediaDevices.getUserMedia({video: {facingMode: "environment", width: {ideal: 1280}, height: {ideal: 720}}, audio: false})` でカメラを取る。
3. `video.srcObject` に流し、`video.play()`。
4. `POST /sessions/{id}/signals` を 1 秒ごとに開始。
5. 状態が `watching` になったら「見守りを始めるよ」と 1 回読み上げる（これがアンロックの確認にもなる）。
6. 「はじめる」の前に学習者が秒数を選んでいたら、1 の前に `patchSettings(id, token, {stuck_seconds})` を送る（既定のままなら送らない）。

- セッションは `/ops` でオペレータが作り、URL（`/device?s=ses_…&t=tok_…`）でスマホに渡す。`/device` を `s=`・`t=` 無しで開いたときは、`openSession` でセッションを自動で作り、同じページに `s=`・`t=` 付きで移る（ADR 0036）。回数の上限（429）なら字幕に「少し待ってから、もう一度開いてね」、サーバに届かないか 5xx なら「つながらなかったよ。少ししたら、もう一度つないでみるね」（どちらも 20 秒後に作り直す）、それ以外の 4xx なら「セッションの URL から開いてね」。
- `startCamera` が throw したら、許可されなかったとき（`CameraDenied`）とカメラの仕組みが無いとき（アプリ内ブラウザなど、`TypeError`）は字幕に「設定からカメラを許可してね。LINE などの中のブラウザなら Safari か Chrome で開いてね」、それ以外（ほかのアプリが使用中、カメラが無い）は「カメラを使えなかったよ。ほかのアプリでカメラを使っていたら閉じて、もう一度はじめてね」を出し、状態は `created` のまま（もう一度「はじめる」を押せる）。

## PC（Mac）で iPhone を連係カメラとして使うとき

- Mac の Chrome では `facingMode: "environment"` は無視され、既定のカメラ（内蔵）が選ばれる。`/device?cam=iphone` のときだけ、`web/lib/camera.ts` は `enumerateDevices()` でラベルに「iPhone」を含む入力を優先し、無ければ既定を使う。`cam` が無ければ iPhone を探さず、`facingMode: "environment"` で取れるカメラを使う。
- 連係カメラは iPhone をロック状態で横向きに近くに置くと候補に出る。出ないときは iPhone を一度ロック解除してから再度ロックする。
- 音声は Mac のスピーカー出力（3.5 mm で会場スピーカーへ）。Meet には「Chrome のタブを共有」でタブの音として乗せる（ウィンドウ共有では乗らない）。

## 音声認識（`web/lib/voice.ts`、高橋が書く）

- `webkitSpeechRecognition`（`lang: ja-JP`、`continuous: false`、`interimResults: true`。途中の文字をデバッグ表示に出すため）。発話ごとに確定した文字列を `onHeard` に渡し、終わったら 0.5 秒おいて自動で再開する（`continuous: true` だと iOS Safari で確定が遅れるため。10/17 夜に待ちを 0 にしたら、iOS が始めた直後に `aborted` で切るようになったので 10/18 に戻した）。エラーの後は 3 秒待つ。マイクを取れないとき（通話中など、`audio-capture`）は 30 秒待って再開する（画面には何も出さない。Issue #39）。始めてすぐ何も聞かずに終わったときは 1 秒待つ（空回りしないため）。読み上げが終わったらすぐ聞き取りに戻る（次の signals を待たない）。非対応なら何もしない。
- 「はじめる」のクリックの中で `primeListening()` を呼び、マイクと音声認識の許可をその場で取る（iOS は操作の直後でないと許可を求められないことがある）。ここで許可されなかったら 1 回と数え、タップで始め直したときと合わせて 2 回続けて許可されなかったら、そのページではもう聞かない（下の「10/19 に足した文言と動き」）。
- `/device` の URL に `voice=0` を付けると聞き取らない（中間発表や動画の撮影で、会場の声に反応させないため）。
- 合言葉は使わない（10/17、ADR 0032）。確定した文（3 文字以上）をすべて `hints`（`trigger: voice`、`utterance` に文）に送り、答えるかどうかは AI が決める。答えないときは 204 で、何も読まない。声の送信は「ヒント」「できた」とは別の印で数え、ボタンを止めない。
- `debug=1` のとき、デバッグ表示に聞き取りの直近 4 つの出来事（start・途中・聞こえた・error・end・タップ）を出し、signals の URL にも `?note=` で付けて送る（サーバのアクセスログで追える）。
- iOS Safari は「Siri と音声入力」が ON でないと動かない。Mac Chrome は動く（音声は Google のサーバで文字にされる。Safari は Apple）。聞き取った文字だけを使い、音声は保存しない。README と 12 に書く。
- ピッチでは使わない（会場のマイクやスピーカーの音を誤認識するため）。製品説明動画の 3 問目で見せる。

## カメラの置き方

- スマホはアーム式スタンドで、紙の真上 35〜45 cm から、紙面全体が入るように。背面カメラ（`environment`）を使う。
- 顔が入らない角度にする。真上から撮れば、入るのは手と紙と机だけ。
- 卓上ライトを紙の斜め上から当てる（影がペン先に落ちないように）。
- 紙は動かさない。シートの位置がずれると差分が大きく出る。
- 画面には映像を表示し続ける。学習者が自分で「何が映っているか」を確認できる。

## 音声合成（`web/lib/speech.ts`、高橋が書く）

- Web Speech API の `speechSynthesis` を使う。`lang = "ja-JP"`。
- 声の選び方：`speechSynthesis.getVoices()` から `lang` が `ja-JP` のものを選ぶ。iOS は Kyoko、Android Chrome は Google 日本語、PC Chrome は Google 日本語か OS の声。`voiceschanged` イベント後に選び直す（最初の `getVoices()` が空のことがある）。
- 速さ `rate = 1.0`、高さ `pitch = 1.0`。`speech` は 35 文字以内なので 5〜6 秒で終わる。
- 読み上げ中に次のヒントが来たら、`speechSynthesis.cancel()` してから新しい文を読む。
- 音声が出ないときも字幕は必ず出す。会場では PC を会場スピーカーにつなぐ（08 参照）。
- 読み上げは VOICEVOX の声（api の `POST /sessions/{id}/tts`、Railway の voicevox サービス）。声は選んだキャラで変わる（イケメンは青山龍星のしっとり、先生は冥鳴ひまり）。作れないとき（503、9 秒で打ち切り、再生の失敗）はブラウザの音声合成で読む。キャラは選んだ時点で `setSpeechCharacter` に渡す。`unlockSpeech` は「はじめる」の中で無音の音声も 1 回鳴らし、iOS で以後の再生を許す（ADR 0035）。

## ボタンの動き

| ボタン | いつ押せるか | 何が起きるか |
|---|---|---|
| はじめる | `created`。見守りの途中でカメラが止まったときも（ほかのボタンの代わりに出る） | 音声アンロック、カメラ開始、`startSession` でループ開始。カメラが止まったときは `startCamera` だけ |
| ヒント | `watching` `still` `cooldown` のときだけ | `requestManualHint()`（フレームを送ってから `POST /hints {trigger: "manual"}`）。段階は現在の段階 |
| できた | `watching` `still` `cooldown` `stuck` のときだけ | `requestCheck()`（フレームを送ってから `POST /check`）。結果を読み上げ。`correct` なら問題番号が進む |
| もう一度はじめる | `ended` のときだけ（ほかのボタンの代わりに出る） | `s=`・`t=` を外した `/device` を開き直し、新しいセッションを作る（ADR 0036） |
| 次へ | `watching` `still` `cooldown` `speaking` `stuck` のときだけ | 確認ダイアログなしで `advance()`。最後なら `ended` |
| おわる | `created` `ended` 以外 | 1 回目でボタンが「本当におわる？」に変わり、4 秒以内にもう一度押すと `end()`（`POST /end` → ループ停止 → カメラ停止）。ブラウザの確認ダイアログは使わない（iPhone の Safari では聞き取りの最中に出ず、押しても何も起きなかった） |
| 記録を見る | `ended`（映像の下に出る） | `getSession`（トークン）→「今日の記録」を重ねて開く。「とじる」で戻る |

`stuck` の数秒間は「ヒント」だけ押せない（自動ヒントと二重にならないため）。「できた」「次へ」は押せて、作りかけの自動ヒントは捨てる（ADR 0037）。
| 静かに | 作らない（Kaizen Sprint） | |

- `hints` の応答の `speech` が `null` のときは読まず、字幕も変えない（Hack Day 版では起きないが念のため）。
- `signals` の応答が `ended` になったらループを止め、終わりの言葉（「状態と表示」の `ended`）を出す。

- 主ボタンは親指で押せる大きさ（高さ 56px 以上）。
- `speaking` 中は主ボタンを無効にする（読み上げの途中で状態が変わると混乱する）。

## フレームの送り方（`web/lib/camera.ts`、高橋が書く）

- `video` を `canvas` に長辺 1024 で描き、`canvas.toBlob("image/jpeg", 0.7)` で JPEG にする。
- 送るタイミング：`signals` の応答に `next_action` が来たら即 1 枚（`send_frame_and_request_hint` のときは、`send_frame` で先に送っていなければ）、「ヒント」「できた」を押した直後に 1 枚。定期的には送らない。
- 送った `frame_id` を保持し、直後の `hints` / `check` に渡す。
- 回線が落ちているときは送らない（キューに溜めない。古いフレームに意味はない）。

## ループ（`web/lib/loop.ts`、高橋が書く）

`startSession(video, sessionId, token, handlers)` が 1 つで次を全部やる。B は `handlers` で受け取った値を表示するだけ。

- `startMotionLoop` で 1 秒ごとに `motion` と `brightness` を取り、`postSignal` を送る。応答を `handlers.onState(resp)` に渡す（`state`、`current_problem_no`、`still_seconds`）。
- 応答の `next_action` が `send_frame` なら `captureFrame → postFrame` を行い、`frame_id` を覚えておく（静止が途切れたら忘れる。ADR 0028）。
- 応答の `next_action` が `send_frame_and_request_hint` なら、覚えた `frame_id` があればそれで、無ければ `captureFrame → postFrame` をしてから `requestHint({trigger: "auto", frame_id})` を行い、応答を `handlers.onHint(resp)` に渡し、`speech` があれば `speak` する。一度成功したら、`signals` の `state` が `stuck` 以外になるのを見るまで再要求しない（失敗したときだけ次の秒に再試行）。
- `state` が `created`・`checking`・`ended` のとき、`onHint` は呼ばれない（字幕の固定文は B が `state` で出す）。
- 最初に `state` が `watching` になったとき「見守りを始めるよ」を 1 回読み上げる（B は書かない）。
- `brightness` を `handlers.onBrightness(b)` に渡す（B が 60 未満で「明るさが足りません」を重ねる）。
- `postSignal` が連続 3 回失敗したら `handlers.onConnection(false)`、成功したら `true`（B が「つながりにくいみたい」を出す）。
- カメラの映像のトラックが止まったら（`ended`・`mute`。通話や、ほかのアプリがカメラを取ったとき）`handlers.onCamera(false)`、戻ったら（`unmute`）`onCamera(true)`。ループは止めない（止まっている間は `camera_ok: false` を送るので、詰まりとは数えない）。
- **声のトリガー**：`watching`・`still`・`cooldown` の間は `startListening` で聞き取り、確定した文（3 文字以上、200 文字で切る）が来たら、フレームを送ってから `answerUtterance` で送る。答えがあれば `onHint` と `speak`、204 なら何もしない。送っている間に来た文は最後の 1 つだけ覚えて、終わったら送る（ADR 0032）。`speaking`・`checking` の間は `stopListening`（自分の読み上げを拾わないため）。聞き取った文字は `handlers.onHeard(text)` に渡す（B は字幕の上に小さく「聞こえた：わからない」と 3 秒だけ重ねて出す。出し入れで字幕の位置を動かさない）。非対応ブラウザでは何もしない。
- `signals`・`hints`・`check`・`advance` のどの応答でも `state` が `ended` になったらループを止める。戻り値の止める関数でも止まる。
- `requestManualHint()` と `requestCheck()` は同じファイルにあり、動いているセッションの id と token を使う。応答を返し、`speech` があれば `speak` する。

## 再接続

- `signals` の送信は 1 秒ごとに `fetch`。失敗しても次の秒にまた送る。連続 3 回失敗したら「つながりにくいみたい」をヘッダに出す。
- サーバが再起動しても `session_token` はそのまま有効（JSON ファイルにある）。状態は `watching` に戻る。

## 字幕の表示

- `state` が `created`・`checking`・`ended` のときは「状態と表示」の表の固定文。それ以外は直近の `display`（`onHint`・`requestManualHint`・`requestCheck` の応答）を 1 つだけ大きく出す。「次へ」で問題が進んだら「次の問題も、見てるよ」に替える。履歴は出さない（記録画面の仕事）。
- 画面の初期 `state` は `created`。ただし最初の `getSession` の `state` が `ended` なら、最初から `ended` の画面（終わりの言葉と「記録を見る」。「はじめる」とキャラ選択は出さない）にする。終わったセッションは始め直せないため。それ以外の `state` は `onState` でだけ更新する（リロードしたら「はじめる」からやり直す）。
- 数式は `display` の文字列をそのまま等幅で出す。自分で整形しない。
- 文字は 24px 以上。机の横 50 cm から読める大きさ。

## モックでの開発

- `NEXT_PUBLIC_MOCK=1` で API はモックになるが、カメラと音声は本物を使う。
- モックの `postSignal` は各状態 5 秒、`watching → still → stuck → speaking → cooldown` の順で一巡 25 秒（03 の表）。`stuck` の 5 秒の間に `onHint` が 1 回来る。モックの `requestHint` は 1 回目 `hint_level1.json`、2 回目から `hint_level2.json`（文が変わるのは正常）。`postCheck` は `check_correct.json`。`checking` と `ended` はモックの一巡に出ないので、字幕の固定文は `state` を手で切り替えて確認するか、B1-6 の実機で見る。これで B は API なしに全状態の表示を確認できる。
- 開発中の表示確認は PC Chrome で `localhost`。スマホでの確認は Vercel のプレビュー URL（HTTPS）で行う。`http://<PCのIP>:3000` ではカメラが取れない。

## 10/18 夜に足した文言と動き

- 「次へ」や signals で問題が進んだら、字幕を「次の問題も、見てるよ」にする（前の問題のヒントや失敗の字幕を残さない）
- カメラが拒否以外の理由で使えないとき（ほかのアプリが使用中、カメラが無い）は「カメラを使えなかったよ。ほかのアプリでカメラを使っていたら閉じて、もう一度はじめてね」
- 最初の `getSession` が 404（消えたセッション）なら、`s=`・`t=` を外して新しいセッションを作る。401（トークンの違い）は今までどおり「つながりにくいみたい」
- 見守りの間は画面を点けたままにする（Screen Wake Lock。使えないブラウザでは何もしない）。画面を隠して戻ったら取り直す
- `openSession` の後は、今のクエリ（`debug`・`voice`・`cam`）を残して `s=`・`t=` を足す
- 時間切れ：`fetch` は 15 秒で打ち切る（signals・frames・tts は今までどおり短い）。ブラウザの声は最長 30 秒で終わったとみなす
- `/log` を鍵なしで開いたら「運営用の画面です。運営の鍵を入れてください。学習者の記録は、/device の『おわる』→『記録を見る』で見られます。」

## 10/19 に足した文言と動き

- `/device` を読み込んでいる間（`useSearchParams` の `Suspense` の間。ビルド時の HTML もこれ）も、白い画面ではなく空の色に「準備しているよ…」を出す。ページの地（`body`）とブラウザの `theme-color` も空の色（sky-400）にし、iPhone で画面を引っぱったときに上下に白い帯を出さない
- セッションを自動で作っている間は「準備しているよ…」。回数の上限（429）で作れなければ「少し待ってから、もう一度開いてね」を出し、20 秒後に自分でもう一度作る
- サーバに届かない（オフライン、時間切れ）か 5xx で作れなければ「つながらなかったよ。少ししたら、もう一度つないでみるね」を出し、429 と同じく 20 秒後に自分でもう一度作る。「セッションの URL から開いてね」は、429 以外の 4xx（サーバが断った）のときだけ
- ヒント・できた・次へが失敗したら字幕に「うまくいかなかったよ。もう一度押してみてね」、回数の上限（429）なら「少し待ってから、もう一度押してね」。状態の食い違い（409）は次の signals で画面がそろうので何も出さない
- 「できた」の判定を待つ間は signals を見ない（`ended` も。判定の応答で終わりを知り、判定の文を読んでから終える）。応答（できた・ヒント・声の答え・次へ）を受け取る前に送って後から届いた signals は、`ended` 以外は無視する（応答で進んだ状態を、古い signals で戻さない）
- 「できた」が失敗したときは前の状態に戻し、字幕に失敗を出す
- 「できた」を押す前に頼んだ自動ヒントと声の答えは、判定を待つ間に届いても、判定の後に届いても捨てる（読まない、字幕も状態も変えない。ADR 0037 の「作りかけの自動ヒントは捨てる」）。ヒント・できた・自動ヒントが重なっても、どれかが先に終わったことで「頼んでいる途中」の印が消えないように、`loop.ts` は頼んでいる数を数える
- 応答（できた・ヒント・声の答え）でセッションが終わるときは、`loop.ts` が `onFinishing` を知らせてからその文を読み、読み終えてから `ended` を知らせる。その間ボタンは止める（読み上げが 20 秒を超えたら待たずに終える。声の合成を 9 秒まで待ち、そのあと読むので 12 秒では足りなかった）。最後の問題の正解なら、字幕は判定の文と終わりの言葉を並べる
- 読み込み（`getSession`）が 404 以外で失敗したら「つながらなかったよ。ページを開き直してね」
- 「はじめる」の前に選んだ秒数を保存できなかったら「秒数を変えられなかったよ。前の秒数のまま見守るね」
- 「はじめる」でカメラが動いたら、字幕を「見守りを始めるよ」にする（前に出ていたカメラの失敗などの字幕を残さない。秒数を保存できなかったときは、上の字幕を出す）
- 「おわる」をサーバに伝えられなかったら、端末は止めたうえで「つながりにくくて、終わったことを伝えられなかったよ」
- 見守りの途中でカメラが止まったら（`onCamera(false)`。通話、ほかのアプリがカメラを使った）、字幕に「カメラが止まったよ。もう一度はじめてね」を出し、ボタンを「はじめる」だけにする。押すとカメラだけを取り直し（ループと問題番号はそのまま）、字幕を「見守りを始めるよ」にする。カメラが自分で戻ったとき（`onCamera(true)`）も同じ。取り直せなければ、最初の「はじめる」と同じカメラの字幕を出す
- 「はじめる」の中（`primeListening`）と、タップ（タッチは `pointerup`、マウスは `pointerdown`。ブラウザが操作の直後と数えるもの）で始め直したときに、合わせて 2 回続けてマイクを許可されなかったら、そのページではもう聞かない（タップのたびに許可を求めない。「はじめる」も操作の直後なので、そこでの拒否も 1 回と数える）
- 途中の聞き取りの文が 2 秒変わらず確定が来ないとき（同じ文が届き続けても数え直さない）、または確定が来ないまま聞き取りが終わったときは、途中の文を確定として送る（iOS で確定が来ない対策。Issue #40）
- 声で読まない知らせ（失敗の字幕、「つながりにくいみたい」、人格の切り替えと記録の読み込みの失敗）は、画面に見えない `role="status"` の枠にも出して読み上げソフトに伝える。ヒントと判定の字幕は同じ文を声で読むので渡さない。「明るさが足りません」は 14px（50 cm 離れて読める大きさ）
- 「となりに座る人」は「はじめる」の前（`created`）だけ選べる。見守りの途中では替えない（選択が出ていると、背の低い画面で字幕とボタンが押し出されていた）。小さい画面と横持ちの配置は「画面の配置」に書いた
- 「はじめる」が消えてほかのボタンに替わったら（見守りが始まったとき、カメラを取り直したとき）、フォーカスを「ヒント」に移す（押したボタンが消えると、フォーカスがページの先頭に落ちていた）
- 記録のシートは開いたら「とじる」にフォーカスを移し、Escape で閉じ、閉じたら「記録を見る」に戻す。開いている間は後ろの画面を `inert` にし、ページ全体のスクロールを止める
- 記録の文言：`/log` の詳細の見出しは「記録：<学習者の名前>」（自動で作ったセッションは「記録：自分で始めた」）、「できた」の結果は「答え合わせ：正解／不正解／読めなかった」
