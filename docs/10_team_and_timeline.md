## 原則（10/16 確定）

- **縦串は「手が止まって 20 秒で固定文 H1 が鳴る」。** GPT は縦串に含めない。Day 1 15:00 の縦串は固定文、GPT の H2 は 15:00〜17:00 に積む。ヒントは 2 段階（H1 固定・H2 GPT）。答え漏れ検査は正規化と部分一致だけで、引っかかったらその問題の固定 H2 に落とす（再生成しない）。SSE は使わない。1 秒ごとの送信と自動ヒントのループは `web/lib/loop.ts` に高橋が Day 1 の 11:00〜13:00 に書き、B は表示だけ。今夜の `loop.ts` はタイマーでモックの状態を一巡させるだけの空実装（事前実装にしない）。
- **契約・モック・部品の型は今夜（10/16）高橋が書く。** `openapi.yaml`（各応答に `example`）、`web/mocks/*.json`、`worksheets/schema.json`、`ws01.json`、`web/lib` の型と空実装。これらは文書と見本で、審査対象のコードではない。当日は Pydantic から契約を再生成しない。
- **クリティカルパスは高橋 1 本。** B・C・D の仕事はどれも落ちてもデモが止まらない。
- **全員が AI（Claude Code か Codex）で開発する。** 手順は `docs/prompts/`。10/17 から担当フォルダの線引きは無く、ハーネス（git フックと CI）が止めるのはハーネスと依存のファイルと危ない操作だけ（ADR 0030）。ただし D の開発は Day 1 13:00〜15:00 のトップページ 1 本だけ（11:00〜13:00 は B・C の受付に専念。10/16 夜のレビューで入れ替えた）。D の本業は実機テスト・中間発表・壇上・進行。
- **決める人を 1 人にする。** 技術と退避は高橋、ピッチと時間は D、文言は 01 の表。
- **切り捨ての順番。** `/log` の集計 → 声の問いへの答え（ADR 0032） → `check` の正誤判定（「できた」は進むだけに） → GPT の H2（H1 固定だけに） → トップページ。20 秒の沈黙と 1 回目の声は落とさない。
- **追加仕様（10/16 夜）。** 止まったと判定する秒数は学習者が `/device` で選ぶ（10 秒・20 秒・30 秒・1 分・3 分・5 分・10 分・20 分）。声で問いかけると答える（Day 1 17:00〜、10/17 21:15 に合言葉から問いへの答えに変えた。ADR 0032）。一度声をかけた後の沈黙（`cooldown_seconds`）が止めるのは自動のヒントだけで、ボタンと声は通る。
- **Day 2 12:30 に「動画用の安定版」をタグし、撮影中はデプロイしない。** デモが安定していなければならない時刻は Code Freeze でなく 12:30。

## 連絡と判断のルール

- Slack のチームチャンネルに、各自 1 時間ごとに「今やっていること・次にやること・困っていること」を 1 行。
- **困ったら即 Slack に書く。** 高橋はビルド待ちなどの切れ目に 2 分で返す。環境が動かない系だけは即割り込み可。節目（11:00・13:00・15:00・17:00）は 15 分ずつまとめて答える。
- **第一受付は D。** 今夜の予行を進行した人として、B・C の環境と Git の詰まりを先に見る。D が 10 分で解けなければ高橋へ。15 分止まったら Slack、30 分止まったら D が席に行く。
- PR は 1 画面 1 本。CI（Linux で `pnpm check`）が緑でないものは見ない。高橋のレビューは 3 点だけ：動くか、頼んでいないファイルを触っていないか、正答が画面に出ていないか。
- 依存パッケージの追加は禁止。必要なら Slack で高橋に。
- 退避の階段を上がる判断は高橋だけ。上がったら D がピッチの文言を変える。
