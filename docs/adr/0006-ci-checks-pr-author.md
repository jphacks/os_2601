# 0006. CI の担当検査は PR の作者の役割で行う

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

CI は PR の変更が、`team.json` で決めた役割の担当フォルダの中にあるかを検査する（`.githooks/guard.mjs --ci`）。ハーネスの初版は `github.actor`（その CI を動かした人）の役割で検査していた。高橋が B の PR の CI を再実行したり main を取り込んだりすると、actor が高橋になり、担当外の変更が takahashi として通る。

## 検討した選択肢

1. `github.event.pull_request.user.login`（PR の作者）の役割で検査する
2. `github.actor` のまま

## 決定

選択肢 1。値は `env` 経由で `run` に渡す。

## 理由

- 担当を決めているのは PR を出した人で、CI を動かした人ではない
- `${{ }}` を `run` に直接埋め込まず `env` で渡せば、値がシェルとして解釈されない

## 受け入れたトレードオフ

- 高橋が B の PR に担当外の修正を足したいときも、B の役割で止まる。そのときは高橋の PR を別に出す
- `team.json` に無いログイン（仮の値のまま、外部の人）は検査を省略する。ログインを埋めるまでは CI の担当検査が効かない

## 再検討する条件

- B・C・D 以外の人が PR を出すようになったとき（省略でなく失敗にする）
