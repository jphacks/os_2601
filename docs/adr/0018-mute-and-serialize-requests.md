# 0018. 読み上げの間は聞き取りを止め、ヒントとチェックは 1 つずつ送る

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

`docs/06` は「speaking・checking の間は stopListening（自分の読み上げを拾わないため）」と書く。サーバの state は 1 秒ごとの signals でしか手元に届かないので、ボタンのヒントや「見守りを始めるよ」を読み上げている間も、手元の state は watching のままで聞き取りが動いている。ヒントの文に「ヒント」が入っていると、自分の声で声のヒントが出て段階が上がりうる。手動・声・自動のヒントとチェックも同時に送りえた。

## 検討した選択肢

1. 読み上げを始めるときに聞き取りを止め、読み終わって次の signals が watching・still・cooldown なら再開する。ヒント・チェック・advance の応答の state はその場で手元に反映し、チェックは送る前に checking にする。要求は 1 つずつにし、自動と声はほかが走っている間は出さない
2. サーバの state だけで切り替える（docs のまま）

## 決定

選択肢 1。ボタンの手動ヒントとチェックは、学習者が押したので優先する（走っている自動・声を待たない）。

## 理由

- 自分の声を拾うと、学習者が頼んでいないヒントが出て段階が上がる（docs/04 の「連打で H2 がすぐ出ないように」に反する）
- 同時に 2 つ読み上げると後の文が前の文を消し、サーバの回数だけが進む

## 受け入れたトレードオフ

- 読み上げが長いと、その間の「わからない」は聞こえない
- 手動を押した直後の自動ヒントは 1 秒遅れる

## 再検討する条件

- 声のトリガーを本番で使い、取りこぼしが問題になったとき
