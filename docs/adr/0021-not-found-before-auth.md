# 0021. 存在しない session id は認可より先に 404 を返す

- ステータス: 提案
- 日付: 2026-10-17

## 文脈

`/sessions/{id}` 以下のエンドポイントで、id のセッションが無く、鍵も無いか間違っているとき、401 と 404 のどちらを返すかは `docs/03` に無い。デバイスの認可は、そのセッションの `session_token` と Bearer を比べて行う（ADR 0007）。

## 検討した選択肢

1. 先にセッションを引き、無ければ 404。あれば認可（401・403）
2. 先に認可し、通ってからセッションを引く

## 決定

選択肢 1。

## 理由

- デバイスの認可にはセッションの token が要るので、引く前には判定できない
- セッションの ID は推測できない乱数（docs/03）なので、404 で存在が分かっても害が無い
- `/device` の URL の打ち間違いが、鍵の間違い（401）でなく「無い」（404）として分かる

## 受け入れたトレードオフ

- 鍵を持たない人にも、ID が存在するかどうかが分かる

## 再検討する条件

- ID を推測できる形にしたとき
