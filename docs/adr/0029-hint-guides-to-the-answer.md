# 0029. ヒントは最初の誤りか次の一歩を示し、答えまで導く

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

10/17 17:00 の本番 iPhone で、高橋が `4x + 5 = 1 → 4x = 1 - 4 → 4x = -4` と書き、最後の行で止まったふりをした。ヒントは 3 回とも 2 行目の誤りを指し、それ自体は的確だったが、答えまで進ませるヒントが無かった。ほかにも 3 つ問題があった。

- 誤りの種類を取り違えた（数字の誤りを「符号を確認して」と言う）
- 詰まりのラベルが「手が止まっている」のような様子で、`/log` の集計に使えない
- 読み上げを 40 文字目で切っていたので、語尾が切れることがある。言葉にさせた記号や数字が「うへん」「マイナスろく」のように崩れる

高橋の要望は「しっかりと答案まで導くヒントを出してほしい」。

## 検討した選択肢

1. AI への指示だけ直す（`api/app/hints.py`）
2. 指示に加えて、「ヒント」ボタンと声でも段階を上げる（状態の規則と契約の説明が変わる）
3. 段階を 3 つ以上に増やす（`max_level` の上限、契約、主張の「2 段階」が変わる）

## 決定

選択肢 1（高橋が選んだ）。

- AI は答案を 1 行目から自分の解き方と比べ、示す所を 1 つ決める。誤りがあれば最初の誤りの行を示し、無ければ答えまでの次の一歩を示す
- 前に出したヒントの所が答案で直っていれば次へ進み、直っていなければ同じ所をもう少し具体的に示す
- 誤りは、誤っている数字や記号そのものを行と位置で指す。符号か数字か計算かを見分ける。正しい値は言わない
- 次の一歩は問いかけにする。段階 2 では操作を 1 つ言ってよい（「両辺を同じ数でわってみて」）。誤りなら出どころと見比べさせる。結果の値や直した後の数字は言わない
- `stuck_point` は数学の内容で書く（「移項の数字」「係数で割る」）
- 読み上げは 35 文字以内、字幕は 50 文字以内で書かせ、切らない。60 文字・80 文字を超えたら、壊れた応答として固定の問い返しに落とす。数字は算用数字のまま、記号だけ言葉にする

## 理由

本物の Gemini（`gemini-3.5-flash-lite`）で、同じ答案の画像を使って直す前と後を比べた（`api/tools/check_guidance.py`。`railway run --service api -- uv run --directory api --with pillow python tools/check_guidance.py` で流す）。

| 答案 | 直す前 | 直した後 |
|---|---|---|
| 2 行目に誤り | 「ニ行目の移行する数字を確認してみよう」 | 「2行目の右辺の4を確認してみよう」 |
| 直した後、最後の行 | （同じ画像で試していない。誤りの無い答案では 2 回目に「左辺の数字を右辺はどうにかして移動させて」とそれた） | 「エックスだけにするには、両辺をどうする?」→ 段階 2「両辺を同じ数でわってみて」 |
| 誤りが直らない、段階 2 | 2 行目の誤りを繰り返し指す | 「1行目のプラス5と、2行目のマイナス4を見比べてみて」 |
| ラベル | 「次の一手が止まってい」（切れている） | 「移項の数字」「両辺を係数で割る」 |

- 契約と状態の規則を変えないので、B・C の画面に影響しない。中間発表（19:10）に間に合う

## 改訂（10/17 17:15、PR #25 のレビュー）

- 応答の項目の順番を `propertyOrdering` で指定し、問題を解いて答案と比べてから、最後にヒントを書かせる（指定しないと Gemini はアルファベット順に書き、ヒントを先に書く）
- 詰まりのラベルも答え漏れの検査にかける。漏れの検査は長さの判定より先にする（漏れを止めた記録が残るように）
- 学習者が正しく書いた式は、読み上げずに行と位置で指させる。読み上げると答え漏れの検査に当たり、固定文になるため
- 読めないときは「途中の式を、1 行ずつ声に出して読んでみて」（前は段階 1 で別の文になっていた）
- 前のヒントは、AI が作ったものだけを番号つきで渡す。固定文は渡さない。写真の問題が前と違えば使わないよう伝える
- 言葉にした記号の「プラス」「かける」も、照合の前に記号に戻す
- `openapi.yaml` の `speech`・`display` の上限を 60・80 文字にした
- ラベルの上限は 12 文字（指示と切る長さを揃えた）

## 受け入れたトレードオフ

- 「ヒント」ボタンを何度押しても段階 1 のままなので、同じ所では具体的になりにくい（前のヒントを渡しているので、少しは変わる）
- AI が誤りを見落とすと、無い誤りを探させたり、誤りを飛ばして次の一歩を問うたりする
- 段階 2 の「操作を 1 つ言う」は、以前の H3（次の一手）に近い。答えの値は言わないので、主張の「答えを言わない」は保てる
- 無料枠の 1 分あたりの回数制限に、10 回ほど続けて呼ぶと当たる（0.3 秒で固定文に落ちた）。1 台で使う分には足りる

## 再検討する条件

- テストで、ヒントが誤りを取り違える、またはそれることが続いたとき
- 「ヒント」ボタンで具体的にならないことが、デモの流れで問題になったとき（選択肢 2 に進む）
