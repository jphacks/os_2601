# 0030. 担当フォルダの線引きをなくし、事故の防止だけ残す

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

10/16 夜のハーネスでは、B・C・D が触れるフォルダを役割ごとに決め、それ以外（`api/`・`web/lib/`・`openapi.yaml`・設定）は高橋だけにした。git のフック、CI、Claude Code の編集前の検査（`.githooks/guard.mjs`）が止める。

10/17 17:40、C が人格モード（教師・友達・お姉さん）を `api/app/personas.py` に作った PR #15 が、担当外として CI で止まった。高橋は、人格まわりの開発を C に任せたい。担当を足すたびに guard を直すより、担当の線引きそのものをなくしたい。

## 検討した選択肢

1. 線引きだけなくす。guard 自体・依存の設定と、事故の防止（force push・`main` への push・デプロイ・依存の追加）は残す
2. 担当は残し、C に `api/app/personas.py` だけ足す
3. guard ごとなくす

## 決定

選択肢 1（高橋が選んだ）。

- 誰でも `api/`・`web/lib/`・`openapi.yaml` を含めて全部触れる
- 高橋だけが変えるのは、ハーネスと依存のファイル（`.github/` `.githooks/` `.claude/` `team.json` `package.json` `web/package.json` `pnpm-lock.yaml` `pnpm-workspace.yaml` `CLAUDE.md` `AGENTS.md`）
- 全員に効く禁止はそのまま（force push、`reset --hard`、`--amend`、危ない `rm -rf`）。B・C・D には、`main` への push、依存の追加・削除、デプロイ、ブランチの強制削除の禁止も残す
- `main` には PR で入れ、高橋がレビューしてマージする。CI に API のテスト（`pytest`）を足し、`pnpm check` と両方が緑の PR だけを見る
- `.role.local` は残す（高橋か、それ以外かを見分けるため）

## 理由

- 線引きは「AI がついでに `api/` を直して壊す」を防ぐためだった。レビューと CI のテストでも止められる。人格のように、担当をまたぐ仕事を振れる方が、残り 1 日では効く
- 事故の防止は、壊れると取り返しがつかないもの（履歴、`main`、本番、依存）だけなので、残しても仕事の邪魔にならない

## 受け入れたトレードオフ

- 同じファイルを 2 人が同時に触ると衝突する。人の担当だったファイルを触るときは、先に Slack で言う
- AI の「ついでの修正」は、レビューでしか止められない。高橋のレビューの負担が増える
- `openapi.yaml` も誰でも変えられる。契約を変える PR には、理由と、壊れる画面を書く

## 再検討する条件

- Code Freeze（10/18 15:00）の前に、レビューで止めきれない変更が続いたとき（担当を戻す）
