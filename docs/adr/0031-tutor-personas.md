# 0031. 家庭教師の人格を /device で選び、ヒントの口調と固定文と正誤の読み上げを変える

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

C が 10/17 15:07 に、人格モードの基盤を `api/app/personas.py` に作った PR #15 を出した。固定の H2 の文型に口調を当てはめる形で、どこからも呼ばれていなかった。ADR 0026・0029 で、ヒントは AI が答案を見て毎回作る形になっているので、そのままでは繋がらない。今回の対象は、家庭教師とイケメンの 2 人格に絞る。

高橋は人格まわりを C に任せたい（ADR 0030 で担当の線引きをなくした）。17:30 に高橋が次の 3 つを決めた。

- 人格は `/device` で学習者が選ぶ
- 変えるのは、AI のヒントの口調だけでなく、固定文と「できた」の読み上げも
- できるだけ早く入れる

## 検討した選択肢

1. 選ぶ場所：セッション作成時（`/ops`）／`/device` で学習者が選ぶ
2. 変える範囲：AI のヒントの口調だけ／固定文と正誤の読み上げも

## 決定

`/device` で選び、固定文と正誤の読み上げも変える（高橋が選んだ）。

- 人格の ID は `teacher`（家庭教師、既定）・`ikemen`（イケメン）の 2 つ。家庭教師は優しい丁寧語、イケメンは落ち着いたタメ口に少しキザなユーモアを添える独自の先輩とする。実在人物の本人再現や声の模倣はしない
- 契約：`SessionSettings` に `persona`（上の 2 つ、既定 `teacher`）を足す。`POST /sessions` の `settings` と `PATCH /sessions/{id}/settings` で変えられ、`GET /sessions/{id}` の `settings` で返る。変えられる状態は今の `PATCH settings` と同じ（`created`・`watching`・`still`・`cooldown`）。未定義の人格 ID は新規入力では受理しない。人格項目のない従来のデータには既定の `teacher` を使う
- 人格の中身は `api/app/personas.py` の 1 か所に置く。人格ごとに次を持つ
  - 表示名
  - AI への口調の指示（`style_instruction`）
  - 固定の問い返し（段階 1・2）と、読めないときの文
  - 「できた」の読み上げ 4 つ（正解、不正解、読めない、失敗）
  - 終了画面の字幕と読み上げ文
- `api/app/hints.py`：Gemini が答案を分析し、選ばれた人格の口調で `speech` と `display` を毎回生成する。`SYSTEM_PROMPT` の提案形を指定する 1 行と、`ANSWER_PROMPT` の言い回しの指示を、人格の `style_instruction` に置き換える。共通の数学的な判断・見る箇所・答えを言わない決まり（ADR 0026・0029）は維持し、口調より優先する。固定文は人格のものを使う
- 固定の H2 テンプレートに当てはめる `render_h2` や、`action`・`variant` の選択方式は採用しない。口調を変えるためだけの Gemini の追加呼び出しは行わない。参考セリフは設定資料として残しても、通常ヒントのランダム再生や長文の自動読み上げには使わない
- `api/app/check.py`：読み上げを人格のものにする（判定は今のまま AI、文は固定）
- 答え漏れの検査は現行のまま全人格で共通に効かせる。サーバーの長さの上限は main と同じく、通常ヒントが `speech` 60 文字・`display` 80 文字、声への回答が 100 文字・120 文字。通常ヒントの生成目標である 35 文字・50 文字とは区別する。固定の問い返しと正誤の読み上げは 35 文字以内、「惜しい」「違う」「答えは」を使わない（docs/05）。テストで両人格を確かめる
- `/device`：キャラクターを選ぶ 2 つのボタンで絵と人格を同時に切り替え、`web/lib/api.ts` の `patchSettings(…, { persona })` を呼ぶ。保存成功後の `teacher` に先生の絵、`ikemen` にイケメンの絵を対応させる。失敗時は元の絵と人格を保ち、保存中や変更できない状態ではボタンを無効にする。`web/lib/api.ts` の型に `persona` を足す
- 「見守りを始めるよ」（`web/lib/loop.ts`）は、Hack Day 版では全人格で共通

## 理由

- 選ぶ場所が `/device` なら、デモの場で家庭教師とイケメンを切り替えて見せられる
- 固定文と正誤の読み上げも変えると、AI が失敗したときや正解したときにも人格が保たれる
- 人格の中身を 1 か所に置けば、C は口調の調整を `personas.py` だけで続けられる

## 受け入れたトレードオフ

- 契約が変わる。`openapi.yaml`、`web/lib/api.ts` の型、`/device` の画面が変わる
- 口調の指示が強いと、AI が答えを言わない決まりを破りやすくなるおそれがある。答え漏れの検査（サーバ）は人格に関係なく効く
- 固定文が人格の数だけ増え、それぞれ答え漏れと長さを確かめる必要がある
- 既定は `teacher` なので、選ばなければ今の動きとほぼ同じ。固定文の言い回しは C が変えうる
- 読み上げは PR #60 の VOICEVOX 対応（ADR 0035）を利用する。保存が確認できた人格から、`ikemen` は `handsome`、`teacher` は `teacher` の声に対応付け、絵・口調・声をそろえる。音声生成と失敗時のブラウザ音声合成へのフォールバックには main の `web/lib/speech.ts` をそのまま使い、`speak(text)` に人格の引数を足したり、人格別の pitch・rate を加えたりしない。エンジンの設定や実機での再生確認は ADR 0035 に従う

## 再検討する条件

- 人格を変えたことで、答え漏れの検査に当たる回数（`leak_blocked_count`）が増えたとき
- 10/18 12:30 の安定版に間に合わないとき（`/device` のボタンを出さず、既定の `teacher` だけで撮る）
