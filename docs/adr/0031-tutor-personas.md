# 0031. 家庭教師の人格を /device で選び、ヒントの口調と固定文と正誤の読み上げを変える

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

C が 10/17 15:07 に、教師・友達・お姉さんの 3 つの人格モードを `api/app/personas.py` に作った PR #15 を出した。固定の H2 の文型に口調を当てはめる形で、どこからも呼ばれていなかった。ADR 0026・0029 で、ヒントは AI が答案を見て毎回作る形になっているので、そのままでは繋がらない。

高橋は人格まわりを C に任せたい（ADR 0030 で担当の線引きをなくした）。17:30 に高橋が次の 3 つを決めた。

- 人格は `/device` で学習者が選ぶ
- 変えるのは、AI のヒントの口調だけでなく、固定文と「できた」の読み上げも
- できるだけ早く入れる

## 検討した選択肢

1. 選ぶ場所：セッション作成時（`/ops`）／`/device` で学習者が選ぶ
2. 変える範囲：AI のヒントの口調だけ／固定文と正誤の読み上げも

## 決定

`/device` で選び、固定文と正誤の読み上げも変える（高橋が選んだ）。

- 人格の ID は `teacher`（先生、既定）・`friend`（友達）・`sister`（お姉さん）。表示名と中身は C が決める
- 契約：`SessionSettings` に `persona`（上の 3 つ、既定 `teacher`）を足す。`POST /sessions` の `settings` と `PATCH /sessions/{id}/settings` で変えられ、`GET /sessions/{id}` の `settings` で返る。変えられる状態は今の `PATCH settings` と同じ（`created`・`watching`・`still`・`cooldown`）
- 人格の中身は `api/app/personas.py` の 1 か所に置く。人格ごとに次を持つ
  - 表示名
  - AI への口調の指示（例：「友達のように、くだけた言い方で。語尾は『〜じゃない？』」）
  - 固定の問い返し（段階 1・2）と、読めないときの文
  - 「できた」の読み上げ 4 つ（正解、不正解、読めない、失敗）
- `api/app/hints.py`：AI への指示の最後に、選ばれた人格の口調の指示を足す。答えを言わない決まり（ADR 0026・0029）が口調より優先することを、指示の中で明示する。固定文は人格のものを使う
- `api/app/check.py`：読み上げを人格のものにする（判定は今のまま AI、文は固定）
- 答え漏れの検査と長さの上限は全人格で共通。固定文は 35 文字以内、「惜しい」「違う」「答えは」を使わない（docs/05）。テストで全人格を確かめる
- `/device`：「はじめる」の前に人格を選ぶボタン（3 つ）を出し、`web/lib/api.ts` の `patchSettings(…, { persona })` を呼ぶ。`web/lib/api.ts` の型に `persona` を足す
- 「見守りを始めるよ」（`web/lib/loop.ts`）は、Hack Day 版では全人格で共通

## 理由

- 選ぶ場所が `/device` なら、デモの場で「友達モード」に切り替えて見せられる
- 固定文と正誤の読み上げも変えると、AI が失敗したときや正解したときにも人格が保たれる
- 人格の中身を 1 か所に置けば、C は口調の調整を `personas.py` だけで続けられる

## 受け入れたトレードオフ

- 契約が変わる。`openapi.yaml`、`web/lib/api.ts` の型、`/device` の画面が変わる
- 口調の指示が強いと、AI が答えを言わない決まりを破りやすくなるおそれがある。答え漏れの検査（サーバ）は人格に関係なく効く
- 固定文が人格の数だけ増え、それぞれ答え漏れと長さを確かめる必要がある
- 既定は `teacher` なので、選ばなければ今の動きとほぼ同じ。固定文の言い回しは C が変えうる

## 再検討する条件

- 人格を変えたことで、答え漏れの検査に当たる回数（`leak_blocked_count`）が増えたとき
- 10/18 12:30 の安定版に間に合わないとき（`/device` のボタンを出さず、既定の `teacher` だけで撮る）
