# 0033. ヒントと声の答えの精度の穴を 6 つふさぐ

- ステータス: 承認
- 日付: 2026-10-17

## 文脈

10/17 夜、本番 iPhone と本物の Gemini で見つかった精度の穴を Issue に起票した（#34〜#45）。高橋が、評価セット（#37）・無料枠の回数制限（#41）・会場での τ の再計測（#43）は対応しないと決め、残りを対応すると決めた。このうち API 側の 6 本をここでまとめて決める。声の聞き取り（#39・#40）は `docs/06` に書く。

## 決定

| Issue | 穴 | 決めたこと |
|---|---|---|
| #34 | 詰まりポイントのラベルが自由記述で揺れ、`/log` の集計がばらける | ラベルは固定の一覧（移項の符号・移項の数字・かっこを外す・係数で割る・分数の計算・同類項をまとめる・計算ミス・式の読み違い・次の一歩・言葉の意味・答えの確認・その他）から選ばせる（`responseSchema` の enum）。一覧に無い文字列が来たら「その他」 |
| #35 | 学習者が正しく書いた式を AI が引用すると、答え漏れの検査に当たって固定文に落ちる | AI に答案の行（`written_lines`）を読み取らせ、紙にすでに書かれている値は検査から外す。守るのは、まだ書いていない答えと途中の値だけ |
| #36 | 1 桁の答えは答え漏れの検査で止められない | 1 桁の答えの値は、答えを言う言い回しと組で照合する（「答えは5」「5だよ」「5になる」「イコール5」など）。行番号や係数の数字には当たらない |
| #42 | 答案が読めないとき、学習者に原因を伝えない | AI に読めない理由（暗い・ぼやけている・紙が枠の外・手やペンで隠れている）を返させ、理由ごとの固定文にする（「紙を枠の中に入れてみて」など）。理由はログにも出す |
| #44 | ボタンと声のヒントは何度頼んでも段階 1 のまま | 同じ問題で 2 回目以降のボタン・声のヒントは段階 2（ADR 0029 のトレードオフを戻す）。声の答えには「同じ問いが続いたら、前より具体的に」と指示する |
| #45 | AI が読み上げ文に記号や仮名の読みを書くと、読み上げが崩れる | サーバで読み上げ文を正規化する（= → イコール、数字の前の - → マイナス、+ → プラス、×・* → かける、÷ → わる、x → エックス、全角の数字 → 半角、漢数字の行番号 → 算用数字）。答え漏れの検査は正規化した後の文にかける |

## 理由

- どれも契約の形（フィールド）は変えない。変わるのは AI への指示・サーバの検査・固定文と、`hints` の `level` の説明文（docs/03、openapi.yaml）だけ
- #35 と #36 は答え漏れの検査の裏表（止めすぎと止め漏れ）なので、一緒に見直す
- #44 は、ADR 0029 で「ボタンでも段階を上げる」を見送ったが、本番で「合ってる？」「次どうすれば」を続けて聞くと同じ返事になることが分かった

## 受け入れたトレードオフ

- ラベルの一覧は方程式（中 1〜2）向け。ほかの単元では「その他」が増える
- `written_lines` の読み取りを AI に頼るので、読み違えると、まだ書いていない値が検査から外れることがある
- 1 桁の答えの照合は言い回しの一覧に頼る。一覧に無い言い方（「5 じゃない？」）は通る
- 読めない理由も AI の判断。暗さは画面の輝度（`min_brightness`）でも別に出る
- 2 回目から段階 2 にすると、ボタンを続けて押すと早く具体的になる（答えの値は言わない）
- 読み上げの正規化は方程式の記号に限る。分数の横線や累乗は言葉にしない

## 再検討する条件

- 「その他」のラベルが半分を超えたとき（一覧を見直す）
- 答え漏れの検査の誤検知と止め漏れを、評価セットで測れるようになったとき（#37 を再開する）
