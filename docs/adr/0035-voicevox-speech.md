# 0035. 読み上げを VOICEVOX の声にし、失敗したらブラウザの音声合成に戻す

- ステータス: 承認
- 日付: 2026-10-18

## 文脈

読み上げはブラウザの音声合成（`speechSynthesis`）で、端末によって声が機械っぽくなる。チームの 1 人が、PC の VOICEVOX で作った wav をスマホのブラウザで鳴らすデモを作り、テザリングの環境で動いた。docs/06 では VOICEVOX は Kaizen Sprint の候補だったが、高橋が 10/18 の 12:30 の安定版（撮影用）に入れると決めた。

## 検討した選択肢

1. API に `POST /sessions/{id}/tts` を足し、Railway に VOICEVOX のエンジン（公式の Docker イメージ、CPU 版）を 2 つ目のサービスとして立てて、api から内部の通信で呼ぶ
2. 手元の PC の VOICEVOX をテザリングでつなぐ（デモと同じ）
3. 今のまま（Kaizen Sprint）

## 決定

選択肢 1（高橋が選んだ）。

- `POST /sessions/{id}/tts`（device のトークン）に `{text}`（1〜120 文字）を送ると、`audio/wav` を返す。エンジンが無い・失敗したときは 503
- api は環境変数 `VOICEVOX_URL` のエンジンに `audio_query` → `synthesis` を呼ぶ。タイムアウト 8 秒、リトライなし
- 声は `/device` で選んだキャラ（#59）で変える。イケメン（handsome）は青山龍星（13）、先生（teacher）は冥鳴ひまり（14）（高橋が選んだ）。`tts` に `character` を送り、サーバが声の番号を選ぶ（どの番号でも読ませられる口にしない）
- エンジンは CPU のスレッドを 4 にする（環境変数 `VV_CPU_NUM_THREADS=4`）。1 では 1 文 5 秒以上、4 で 1.1〜1.6 秒だった
- `web/lib/speech.ts` の `speak` は、セッションが分かっていれば `tts` の音声を鳴らし、失敗したら今の `speechSynthesis` で読む。`unlockSpeech` は、iOS で以後の再生を許すため、「はじめる」の中で無音の音声も 1 回鳴らす
- `speak`・`unlockSpeech`・`stopSpeaking` の名前と引数は変えない。`loop.ts` は開始のときに、どのセッションの声か（id とトークン）を `speech.ts` に渡す
- README と動画に「VOICEVOX:青山龍星」「VOICEVOX:冥鳴ひまり」のクレジットを出す

## 理由

- 選択肢 2 は本番（Vercel と Railway）では使えない
- 文字を受けて音声を返す口は、トークンと文字数の上限で、誰でも好きな文を読ませられる口にしない
- 失敗してもブラウザの音声合成で読むので、声が止まらない

## 受け入れたトレードオフ

- 音声を作る時間（1 文 1〜2 秒）だけ、読み上げが遅れる。先読みの待ち 0 秒は、文字が出てから声が出るまでの遅れになる
- Railway のメモリを 1〜2GB 使い、料金が増える。エンジンの起動に数十秒かかる
- iPhone では、声の聞き取りが動いている間に音声を鳴らすと、音が受話口から小さく出ることがある。実機で確かめる
