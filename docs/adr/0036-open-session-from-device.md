# 0036. `/device` を開くだけで始められるよう、セッションを自動で作る

- ステータス: 承認
- 日付: 2026-10-18

## 文脈

セッションは運営が `/ops` か `tools/create_session.py` で作り、`/device?s=…&t=…` の URL を配っていた。10/18 15:20 に高橋が `/device` を URL だけで開き、読み込みも警告もなく「はじめる」が押せないままになった。審査員が本番の URL を開いても始められない（Issue #71）。

## 検討した選択肢

1. `s=`・`t=` が無いとき、公開の口 `POST /sessions/open` でセッションを作って `/device?s=…&t=…` に移る
2. 固定のデモ用セッション URL を配る
3. 今のまま（運営が発行）

## 決定

選択肢 1（高橋が選んだ）。

- `POST /sessions/open`（認証なし）は、FREE・live・既定の設定でセッションを作り、`POST /sessions` と同じ応答を返す。`learner_label` は「自分で始めた」
- 乱用の対策：IP ごとに 1 分あたり 3 件（10/19 に 10 件。ADR 0039 の追記）、全体で 1 分あたり 30 件まで（超えたら 429 `RATE_LIMITED`）。IP は `X-Forwarded-For` の最後の値（Railway の edge が付ける値で、クライアントが書いた値は前に並ぶ）。自動で作ったセッションは 30 分で終わる（`auto_end_at`。状態機械が時刻で終わらせるので、一覧にも「終わり」と出る）。終わって 1 日たったら記録から消す（ADR 0039 で 2 時間に縮めた）。環境変数 `OPEN_SESSIONS=0` で口を閉じる（404）
- `/device` は `s=`・`t=` が無ければ `open` を呼び、返った id とトークンで同じページに移る。口が閉じているか失敗したときは「セッションの URL から開いてね」を出す
- 「おわる」の後は、`/device` を開き直せば新しいセッションで始まる。終わったセッションを始め直す設計は変えない（#61）
- 固定のデモ用 URL は作らない。複数人が同時に開くと動きが混ざる

## 理由

- URL を知っていれば誰でもすぐ始められ、審査員も試せる
- 作成の口を開いても、Gemini の無料枠と VOICEVOX が他人に使われる量は、回数と寿命の上限で抑えられる

## 受け入れたトレードオフ

- 公開の口なので、上限の範囲では誰でもセッションを作れる。記録画面には「自分で始めた」セッションが並ぶ
- IP での制限は、同じ回線の複数人（会場）では 1 分に 3 人までになる
