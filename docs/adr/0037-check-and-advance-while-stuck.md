# 0037. stuck の間も「できた」「次へ」を受け、作りかけのヒントは捨てる

- ステータス: 承認
- 日付: 2026-10-18

## 文脈

`stuck`（手が止まって詰まりと判定した後、自動ヒントが出るまで）は、`POST /check` も `POST /advance` も 409 で、抜ける道は自動ヒント・5 秒の信号途絶・`End` だけだった。詰まった直後に解き終えて「できた」を押しても 409 になる。自動ヒントの合成が失敗し続けると、端末が信号を送る限り `stuck` に閉じ込められる（Issue #65、品質確認の指摘）。あわせて、ヒントの合成中に問題や人格が変わって 409 を返す経路と、想定外の例外で 500 になる経路で `pending_until` を戻さず、最長 12 秒ヒント・できた・設定変更が 409 になっていた。

## 検討した選択肢

1. `stuck` と、ヒントの合成中（`pending_until` あり）でも「できた」「次へ」を受け、作りかけのヒントは捨てる
2. 今のまま（`stuck` は自動ヒントでしか抜けない）

## 決定

選択肢 1（高橋が「全部対応して」と決めた #65）。

- `CheckRequested` と `Advance` は `stuck` でも受理する。受理したら `pending_until` を消す。遅れて届く `HintIssued` は状態が合わないので `Rejected`（自動ヒントの要求は 409 を返し、端末は捨てる）
- ヒントの合成が 409（問題や人格が変わった）か例外で終わるときは、`HintAbandoned` を適用して `pending_until` を消してから失敗を返す
- `stuck` で `force_stuck` や自動ヒントを受ける規則は変えない

## 理由

- 学習者の操作（できた・次へ）は、サーバの裏の処理（ヒントの合成）より優先する
- `pending_until` は「同じ処理を二重に走らせない」ための鍵で、処理が終わったら必ず戻す

## 受け入れたトレードオフ

- 「できた」の直後に自動ヒントが届いていれば、そのヒントは捨てられる（詰まりの回数には残る）
