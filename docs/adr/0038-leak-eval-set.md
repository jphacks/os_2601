# 0038. 答え漏れの検査に評価セットを置き、1 桁の言い回しと分数を止める

- ステータス: 承認
- 日付: 2026-10-18

## 文脈

「答えを言わない」の最後の砦は `api/app/leak.py` の照合だが、1 桁の答え（x = 5）は「答えは 5」「5 になる」のような定型句でしか捕まらず、「右辺に 5 を書いてみて」「5 が正しいよ」「答えは、5。」が通っていた。答えが 1/2 のときの「2分の1」「0.5」も照合されず、`reading.py` は「x²」を「エックス2」と読んでいた（Issue #64、品質確認の指摘）。検査を厳しくすると固定文に落ちる回数が増えるので、測りながら直す必要がある。

## 検討した選択肢

1. 評価セット（答え・途中の値・ヒント文・止めるべきか）を JSON で持ち、テストで全件の判定を確かめる。そのうえで言い回しと分数の照合を足す
2. 1 桁の答えは数字が単独で現れたら全部止める
3. 今のまま

## 決定

選択肢 1（高橋が「全部対応して」と決めた #64）。

- `api/tests/leak_cases.json` に、止めるべき文と通すべき文を対で持つ。`test_leak.py` が全件を照合し、`api/tools/eval_leak.py` が見逃しと誤検知の数を出す
- 1 桁の答えの言い回しに「{v} を書いて／入れて」「{v} が正しい／正解」「x は {v}」「文末の {v}」を足す。「2行目の 5 を見てみて」「15 を右辺に」は通す
- 分数：`normalize` が「2分の1」「二分の一」を `1/2` にそろえ、`leak_strings` が `1/2` に `0.5`（有限小数のときだけ）、`0.5` に `1/2` を足す
- `to_reading` は `x²` を「エックスの2乗」と読む

## 理由

- 選択肢 2 は「2行目の 5」「15」まで止めて、固定文に落ちる回数が増えすぎる
- 評価セットがあれば、指示や照合を変えるたびに見逃しと誤検知を数で見られる

## 受け入れたトレードオフ

- 言い換え（「2 倍して 10 になる数」）は止められない。README の既知の制約のまま
- 評価セットは人が書いた文で、AI が実際に出す文の分布とは違う。本物の AI で出た文を見つけたら足す
